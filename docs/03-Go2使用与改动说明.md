## 3. Go2 模型关键信息（读模型时看什么）

加载的文件是 `scene.xml`（本体 + 地面 + 灯光），它用 `<include>` 引入 `go2.xml`。

| 属性 | 值 | 含义 |
|------|-----|------|
| `nq` | **19** | 7 维浮基（3 位置 + 4 四元数）+ 12 个关节 |
| `nv` | **18** | 6 维浮基速度 + 12 个关节速度 |
| `nu` | **12** | 12 个执行器 |
| `nkey` | **1** | 一个关键帧 `home`（能站住的姿态） |
| `compiler angle` | `radian` | **角度单位是弧度**（和 MJCF 默认的「度」不同！） |

### 12 个执行器 = 4 条腿 × 3 个关节

```
FL_hip  FL_thigh  FL_calf      (前左：外展 / 大腿 / 小腿)
FR_hip  FR_thigh  FR_calf      (前右)
RL_hip  RL_thigh  RL_calf      (后左)
RR_hip  RR_thigh  RR_calf      (后右)
```

### 关键：它是**力矩电机**，不是位置伺服

```xml
<motor ctrlrange="-23.7 23.7"/>      <!-- ctrl 是【力矩】单位 N·m -->
<default class="knee"><motor ctrlrange="-45.43 45.43"/></default>
```

所以**不能**直接把「目标角度」写进 `ctrl`，必须自己算：

```python
tau = kp * (q_target - q) - kd * qd      # PD 控制
data.ctrl[:] = tau
```

### `home` 关键帧

```xml
<key name="home"
     qpos="0 0 0.27 1 0 0 0   0 0.9 -1.8   0 0.9 -1.8   0 0.9 -1.8   0 0.9 -1.8"
     ctrl="0 0.9 -1.8  0 0.9 -1.8  0 0.9 -1.8  0 0.9 -1.8"/>
```

- `qpos` 前 7 个是浮基（`0 0 0.27` = 站在 z=0.27 处，`1 0 0 0` = 无旋转的四元数）
- 后面 12 个是关节角，每条腿都是 `hip=0, thigh=0.9, calf=-1.8`（弧度）
- 用一行代码就能摆到这个姿态：

```python
mujoco.mj_resetDataKeyframe(model, data, model.key("home").id)
```

## 4. `scripts/run_go2.py` 干了什么

**控制回路（每一步都重复）：**

```
读状态 → 算目标角度 → 算 PD 力矩 → 写 ctrl → mj_step
```

对应代码：

```python
q  = data.qpos[7:]       # 12 个关节角（跳过前 7 维浮基）
qd = data.qvel[6:]       # 12 个关节速度（跳过前 6 维浮基）
target = q_home + 步态    # 目标关节角
data.ctrl[:] = kp * (target - q) - kd * qd
mujoco.mj_step(model, data)
```

**两种模式：**

| 模式 | 做什么 | 用途 |
|------|--------|------|
| `--mode hold` | 目标就是 `home` 姿态，PD 把它按住 | 让机器人站住 |
| `--mode trot` | 在 `home` 上叠加对角步态正弦 | 让它走起来 |

对角步态（trot）：`FL+RR` 一组同相，`FR+RL` 另一组反相。

**实测结果（已验证）：**

| 命令 | 结果 |
|------|------|
| `--mode hold`（kp=40, kd=1） | 站住，高度 0.242 m（home 是 0.27，PD 有静差） |
| `--mode hold --kp 100 --kd 2` | 站得更稳，高度 0.264 m |
| `--mode trot`（默认参数） | **5 秒前进 +2.43 m，全程站立** |

默认步态参数：`--freq 2.4 --amp-thigh 0.55 --amp-calf 0.60`（单位**弧度**），
这组是扫描调出来的，不是理论最优。

## 5. 怎么复现


## 6. 以后想改 Go2 模型的正确姿势

1. **不要**改 `models/unitree_go2/` 里的原始 XML（保持和官方一致，便于将来对比/更新）。
2. 复制一份再改：
   ```bash
   cp models/unitree_go2/scene.xml models/unitree_go2/scene_my.xml
   ```
   （或者整目录复制成 `models/unitree_go2_mod/`，注意 `meshdir="assets"` 是相对路径，
   整目录复制最省事。）
3. 改完用 `diff` 和原版对比，确认只动了你想动的地方。
4. 如果改了 `go2.xml` 的浮基高度、质量、摩擦等，`run_go2.py` 的步态参数可能需要重新扫描。

## 7. 已知局限（诚实说明）

`run_go2.py` 的 trot 是**开环步态**：

- ❌ 不能上坡、不能过台阶
- ❌ 被外力推一下就可能翻
- ❌ 机身质量/摩擦一变，参数就失效

这是「手写步态」的固有局限，不是 bug。
想让它真正鲁棒地跑，需要**强化学习**（见 `docs/02-四足机器人仿真路线.md` 第 5 节）。
